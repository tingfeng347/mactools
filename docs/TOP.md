## 用户要求与采用方案

用户要求增加 `mato`（全称 `ma top`），采用 btop 类似界面，持续监测 CPU、GPU、磁盘、网络、内存；支持进程搜索、结束进程、按内存大小过滤、切换主题。后补要求：“内存占用要少，界面要流畅”，已授权开始实现。

沿用 Python 3.9+ 标准库；curses 局部重绘，原生 Mach/libproc/IOKit/sysctl 采集，不逐进程启动命令。GPU 利用率优先直接读 IOKit；已安装 macmon 时，单个有界 JSON 采集流补充频率、功耗及温度。无指标显示不可用，不用 0 冒充。

采集线程只发布最新快照；界面输入不等待采集；历史最多 120 个点。默认 1 秒采样。完整进程命令按搜索/详情需要缓存，进程消失后回收缓存；搜索缓存 5 秒过期，详情强制重读；命令缓存限制 4 MiB，长命令换行不缓存重叠后缀。使用 PID + 启动时间保持选择及核对结束目标；确认默认取消，普通/强制结束分别确认。系统权限不自动提升。

界面继承用户提供截图和已认可布局：CPU/GPU 顶部，内存/磁盘/网络左栏，进程表右栏，底部快捷键；窄屏按 Tab 切换概览/进程。终端默认、深色、浅色、Nord、Gruvbox 主题。主题、布局和刷新间隔保存，搜索/过滤不保存。界面使用项目中英文设置。

## 验收与性能目标

- CLI：`ma top`/`mato` 等价，帮助、补全、脚本安装/卸载完整接入。
- 监控：各类资源可用，速率基于单调时间差；首个速率采样、缺失或重置的计数明确处理。网络选择具体网卡避免 VPN 重复统计。APFS 容量不按卷相加。
- 进程：名称/PID/命令搜索与内存上下限/用户过滤组合；排序保持选择；固定顺序不冻结值；目标已退出/身份变化/权限不足可见。
- 界面：宽/窄屏、无结果、采集失败、详情、确认、主题和退出恢复终端。
- 目标（非已测结果）：主进程及采集子进程合计 RSS ≤ 50 MiB，静置平均 CPU ≤ 单核 2%，通常按键反馈 ≤ 50 ms，连续 1 小时内存无持续增长。
- 测试边界：公开 CLI、采集快照/过滤/信号 API、伪终端真实交互。只结束本次测试创建的进程；不真实安装/卸载宿主软件。

## 使用

仓库目录运行 `./bin/mato` 或 `./bin/ma top`。例如：

```bash
./bin/mato --theme nord
./bin/mato --sort memory --min-memory 500MiB
./bin/mato --search chrome --min-memory 200MiB --max-memory 2GiB
./bin/mato --interface en0 --disk disk0
./bin/mato --json --samples 2
```

`/` 搜索；`f` 内存/用户过滤；`m/c/p/a` 内存/CPU/PID/名称排序，重复反向；方向键选择，PgUp/PgDn 翻页；`Enter` 详情，详情用方向键滚动完整命令；`Space` 固定顺序、继续更新数值；`k` 发送 SIGTERM，`K` 发送 SIGKILL，均只在确认框按 `y` 后执行。`t` 主题；`Tab` 窄屏切换页面；`n` 网卡，`d` 物理磁盘，`v` 容量卷；`-/+` 缩短/延长采样间隔（每次 100 ms）；`?` 帮助，`q` 退出。支持鼠标选行；滚轮事件取决于终端/ncurses 支持。

内存大小参数以 1024 为进制，`500M`、`500MB`、`500MiB` 均为 500 MiB。上下限含边界，和搜索、用户条件取交集。搜索按完整输入做不区分大小写的子串匹配。权限限制的完整命令不可搜索，仍能按 PID 和名称搜索。

进程内存为 RSS，包含共享驻留页，不表示结束后必然释放同等大小。系统“已用”为总量减空闲页和非活跃页，与活动监视器的应用内存/压力口径不同。CPU 总占用为 0–100%，进程 CPU 以单核 100% 计，可超过 100%。首次速率样本为 `--`；计数回退或设备新出现时重新建立基线。

磁盘容量按所选挂载卷展示，不累加 APFS 共享容量；读写速度按标题中的物理磁盘展示，容量卷和物理磁盘分别由 `v/d` 选择。网络只展示标题中的单个网卡，累计流量为该网卡系统计数，不叠加 VPN 与底层链路。历史保留 120 个采样点，默认 1 秒时约为 2 分钟。

交互正常退出后保存主题、采样间隔、窄屏页面到项目配置目录的 `top.json`；搜索/过滤不保存。JSON 模式不保存设置。未安装 macmon 时原生 GPU 利用率仍可使用；`--no-macmon` 禁用可选采集器。

## 2026-11-08 kitty 刷新修复与控件

用户反馈：界面重复数字、残影；希望右上角像 btop 一样调节刷新间隔，并按信息含义丰富颜色。

最小复现在原生 `TERM=xterm-kitty` 的 PTY 中直接运行 curses 绘制长横线/图表：本机 Apple ncurses 6.0（20150808）的 REP 字符重复能力将 U+2501 截断为控制字节 0x01、U+2582 截断为无效 UTF-8 字节 0x82，再发送重复指令。结果会重复上一数字、丢失边框、出现替代字符。此前 tmux 检查使用的终端描述没有触发这条路径。

修复：仅当老版本 ncurses（6.0 及更早）与 `xterm-kitty` 组合时，在本进程 curses 会话中使用兼容的 `xterm-256color` 终端描述；退出恢复原环境，不修改 kitty 或 shell 配置。现代 ncurses 与其他终端保留原终端类型。回归直接验证 kitty 类型的真实 PTY 字节流，覆盖连续刷新、Unicode 图表/边框，原错误测试修复前失败、修复后通过。另用终端模拟器解析输出，检查宽/窄屏标题位置和完整边框。GUI 抓图工具不允许访问 kitty，未将这些检查描述为真实 GUI 截图验收。

右上角 `[-] 1000 ms [+]` 可点击；`-` 缩短、`+` 延长采样间隔，每次 100 ms。点击毫秒数或按 `i` 可直接输入 500–60000 ms，Enter 应用，Esc 取消；修改立即唤醒采集，正常退出后保存。用键盘、鼠标调整及精确输入/无效输入的真实 PTY 测试验证。

颜色固定对应 CPU 绿、GPU 紫、内存琥珀、磁盘蓝、网络青，标题/曲线/数值一致；进程表只有 CPU≥20% 和 RSS≥512 MiB 的数值使用对应强调色，选中行继续使用统一选择背景，错误仍为独立告警颜色。颜色不改变排序或过滤。

修复后以 `TERM=xterm-kitty` 真实 PTY、160×44、1 秒采样，测量 30 秒：RSS 24.09–24.38 MiB，CPU 平均占单核 0.70%，5 次按键反馈最大 0.85 ms。[本轮原始数据](top-refresh-performance.json)。这是短时性能证据，一小时验证仍未完成。

### macOS CI 终端描述兼容

提交 `c005436` 的 [macOS CI](https://github.com/tingfeng347/mactools/actions/runs/42438956988) 中，Intel/Python 3.9 通过，Apple Silicon/Python 3.13 的两个 kitty PTY 测试因 `setupterm: could not find terminal` 失败。原兼容分支只处理老版本 ncurses，新版在缺少 `xterm-kitty` 描述时仍会启动失败。

现在新版 ncurses 先检查 kitty 描述能否加载，缺失时在当前 curses 会话使用 `xterm-256color`；描述可用时保留 kitty，退出时恢复原 `TERM`。回归测试用终端查找替身覆盖新版描述缺失、描述可用与普通 xterm 三种情形；真实 PTY 测试继续验证绘制与交互。
